## Установка и первый запуск

Debug APK: `gatekeeper-0.1.14-debug.apk` (фактическую версию сверить с version.properties).
Для обновления существующего Gatekeeper нужна та же подпись. Debug APK не заменит
установленный релиз с другим ключом; ради проверки не удалять действующий рабочий
профиль с данными. Использовать совместимую подпись или отдельное тестовое устройство.

Открыть Gatekeeper и завершить обычную настройку. В «Файлы и медиа» проверить:
«Общие фото и скриншоты» и оба направления включены в новой установке.
Если пользователь ранее явно выключал старый импорт, его выбор сохраняется.
Предоставить доступ ко всем фото через «Разрешить доступ к фото и возобновить обмен».
Проверить уведомления службы и статус каждого направления; открыть основной экран
Gatekeeper для первичного подключения к рабочему сервису.

## Основные сценарии

1. После первоначального подключения сделать новый скриншот в рабочем приложении.
   В личном Telegram открыть вложения. Убедиться, что снимок можно выбрать и отправить
   в «Избранное» без открытия File Shuttle.
2. Снять новое фото штатной камерой личного профиля. В рабочем Avito открыть создание
   объявления и его собственный выбор фото. Проверить видимость и загрузку в черновик;
   объявление не публиковать. Самому Avito должен быть предоставлен доступ к снимку.
3. Повторить после ухода Gatekeeper с экрана, удаления его окна из списка недавних,
   блокировки и длительного простоя. Сравнить минимум 30 небольших снимков и записать
   время окончания записи, публикации копии и появления в UI приложения.
4. Проверить фактическую папку рабочих скриншотов на Oppo. По умолчанию источник
   ограничен `Pictures/Screenshots`; если прошивка пишет иначе, это отдельный
   подтверждённый случай для расширения списка, а не повод читать всё хранилище.

## Сбои и выключение

- Выключить только камеру: новые личные фото в Avito не появляются, рабочие скриншоты
  продолжают приходить в личный профиль.
- Выключить общий режим: новые копии прекращаются, уже скопированные остаются.
  Перезапуск приложения и обновление не включают его обратно.
- Включить снова: старый архив и снимки выключенного периода не выгружаются.
- Выключить рабочий профиль, снять новое фото, включить профиль и открыть Gatekeeper:
  недоставленное должно догнаться при прежнем включённом направлении.
- Отозвать фото-доступ, затем вернуть; проверить отображение причины и повтор доставки.
- Проверить отсутствие дублей при повторном открытии Gatekeeper, переподключении,
  одинаковых именах файлов и удалении уже доставленной копии.
- Перезагрузить телефон и записать поведение до/после открытия Gatekeeper.
  В текущей реализации восстановление после полной потери обоих Binder требует
  открытия приложения; этот сценарий не считать полностью бесшовным.
- Убийство процесса и сбои хранилища воспроизводить на выделенном тестовом стенде,
  не через force-stop приложений/очистку данных на рабочем телефоне пользователя.

## Инструментальные проверки хранилища

`MediaExchangeStorageTest` использует отдельную тестовую БД и собственные MediaStore
записи, удаляемые после теста. На подготовленном выделенном стенде установить
debug APK и `app/build/outputs/apk/androidTest/debug/app-debug-androidTest.apk`, затем:

```sh
adb -s <test-device> shell am instrument -w \
  -e class io.gatekeeper.MediaExchangeStorageTest \
  io.gatekeeper.test/androidx.test.runner.AndroidJUnitRunner
```

Зафиксировать отдельные результаты: JVM, lint/detekt, сборка APK, инструментальные
тесты, реальные Telegram/Avito, фон и восстановление ColorOS. Сборка тестового APK
не означает выполнения инструментальных тестов.
