# Чеклист проверки Shelter на Oppo Find X9 Pro / ColorOS 16

## РЕЗУЛЬТАТЫ ПРОГОНА 10.08.2026

Устройство: `CPH2791`, Android 16, SDK 36. Все команды -- только на чтение, состояние устройства не менялось.

**Пользователи.** `0` -- основной, `11` -- `system_clone` (штатное "Клонирование системы" ColorOS, Shelter там не установлен), **`12` -- Work profile**, тип `android.os.usertype.profile.MANAGED`, состояние `RUNNING_UNLOCKED`, создан 44 дня назад. Profile Owner профиля 12 -- `net.typeblog.shelter/.receivers.ShelterDeviceAdminReceiver`.

**T1 -- сборка.** `versionName=1.9.1`, `versionCode=445`, **`targetSdk=34`**, `minSdk=24`. Это релизная сборка с F-Droid, не master. Установлена 2026-06-26.
Следствие: приложение **не подпадает** под поведенческие изменения targetSdk 35 и 36. Edge-to-edge и predictive back на него сейчас не действуют -- шаг 3 плана из аудита теряет срочность.

**T6 -- ПРОВАЛ, воспроизведено.** `adb shell pm list packages --user 12` отдает:
`Error: java.lang.SecurityException: Shell does not have permission to access user 12`
То же, что #2072 на HyperOS 3 / Android 16. **Значит баг не MIUI-специфичный.** Уточнение сильнее форумного: `--user 11` (system_clone) шеллу доступен, а managed profile -- нет. Ограничение именно на управляемый профиль.
Следствие: путь через adb в профиль закрыт. Сценарии удаления системного софта внутри профиля отпадают. T7 через adb недоступен -- перечислить пакеты профиля можно только через UI Shelter, пункт "Все приложения".

**T3 -- предусловия уже выполнены, настраивать нечего.**
`CrossProfileDocumentsProvider` в `enabledComponents` и у user 0, и у user 12.
`MANAGE_EXTERNAL_STORAGE` -- allow в обоих. `SYSTEM_ALERT_WINDOW` -- allow в обоих.
Остался только функциональный тест: видит ли Shelter системный менеджер "Файлы" от ColorOS и выносится ли скриншот из профиля.

**Состояние компонентов.** В профиле 12 отключены `MainActivity` (штатно -- прячет иконку внутри профиля) и `PaymentStubService`. Заглушка NFC включена в основном профиле -- как и задумано.

**Падений нет.** Буфер `crash` -- 998 строк, записей по `net.typeblog.shelter` ноль. T2 без воспроизведения не закрывается: либо ты ни разу не жал "Ярлык групповой заморозки", либо краша на ColorOS нет.

**Процессы.** На момент первых замеров Shelter не был запущен ни в одном профиле. Позже поднялся в обоих: `15516/u0a365` и `16786/u12a365`. Для T4 важно: без живого процесса в профиле автозаморозка работать не может.

**T2 -- НЕ ВОСПРОИЗВОДИТСЯ.** Нажатие "Ярлык групповой заморозки" краша не дало: буфер `crash` не вырос (998 строк), записей по Shelter ноль. Ярлык создан и запиннен:

```
Pinned: shelter-freeze-all        Launcher: com.oplus.dmp
ShortcutInfo {id=shelter-freeze-all, flags=0x86 [PinIc-rStr]
  shortLabel=Заморозить
  intents=[Intent { act=...PUBLIC_FREEZE_ALL cmp=.../.ui.DummyActivity }]
  iconRes=2131623936[mipmap/ic_freeze], bitmapPath=null}
```

`bitmapPath=null` и `Total bitmap size: 0` -- лаунчер Oppo принял adaptive-icon через `Icon.createWithResource` штатно. **Гипотеза из [4pda_code_verification.md](4pda_code_verification.md) раздел 3 окончательно снята.** Баг #1706 -- специфика чужой прошивки или лаунчера, не Android 16. Пункт выбывает из плана доработок.

**T4 -- корневая причина найдена и устранена настройкой.**
До правки: `OplusHansManager: freeze uid: 10365 ... scene: LcdOn` и то же для `1210365` -- ColorOS замораживал оба процесса Shelter примерно через 5 секунд после ухода в фон, через собственный HANS-фризер (`OplusBinderProxy ... calling: OFreezer`, `ProxyButDropTypes:[26, 10, 32, 6]`). Shelter отсутствовал в `deviceidle whitelist`.
После добавления в whitelist и настроек ColorOS (фоновая активность + автозапуск, вручную, в обоих профилях): 4.5 минуты с заблокированным экраном, `15516` и `21374` живы, заморозок Shelter ноль. Контроль: в том же окне 18 событий HANS по другим приложениям -- логгер активен, отсутствие записей по Shelter значимо.

Замечание: в `deviceidle whitelist` попала запись только `user,net.typeblog.shelter,10365`, uid рабочего профиля `1210365` в списке не значится. Тем не менее процесс в профиле выжил -- значит решают настройки ColorOS, а не AOSP-слой.

**Побочное наблюдение, важное для цели.** HANS морозит содержимое рабочего профиля и без Shelter (`ru.vk.store`, `ru.mts.mymts`, `ru.lewis.dbo`, `com.yandex.browser` -- uid с префиксом 12). Но размораживает по событию: `unfreeze uid: 1210485 ru.vk.store reason: Packet`. Это cgroup-заморозка до первого сетевого пакета, а не отключение. **Системный фризер не заменяет `setApplicationHidden`**: пуш будит приложение и оно отрабатывает. Для задачи "госсофт не должен жить фоном" полагаться на ColorOS нельзя.

## Подготовка

```bash
adb shell pm list users
```

Запомни ID рабочего профиля -- дальше он `<N>`. Обычно 10 или 11.

```bash
adb shell dumpsys device_policy | grep -iE "profile owner|admin"
```

Должен быть `net.typeblog.shelter` как Profile Owner.

## T1. Какая у тебя сборка

## T2. Краш ярлыка групповой заморозки

Самое ценное. Баг #1706 на Android 16, причина не установлена, моя гипотеза про adaptive-icon документацией не подтвердилась. У тебя A16 -- воспроизведешь.

```bash
adb logcat -c
```

Дальше на телефоне: Shelter -> три точки -> **"Ярлык групповой заморозки"**.

```bash
adb logcat -d -b crash > ~/crash_freezeall.txt
adb logcat -d -b main *:E | tail -100 > ~/err_freezeall.txt
```

Контрольный опыт -- по #1706 ярлык отдельного приложения создается нормально, а групповой крашится. Проверь оба:
долгий тап на приложении в списке -> **"Ярлык разморозки и запуска"**.

**Прислать:** оба файла. Если краша нет -- так и скажи, это тоже результат: значит баг не универсален для A16, а специфичен для прошивки или лаунчера.

## T3. Перенос файлов -- твой исходный сценарий

Тот самый кейс: вытащить QR или скриншот из профиля наружу.

Включить надо в **обоих** профилях:

1. Настройки Shelter -> **"Перенос файлов"** -- галка в основном и в рабочем.
2. Разрешение **"Доступ ко всем файлам"** -- обоим экземплярам Shelter, основному и рабочему.
3. Разрешение **"Поверх других приложений"** -- тоже обоим.

Пропуск любого из шести пунктов -- фича молча не работает. Это ровно то, на чем сидят люди в #2135.

Проверка: Shelter -> три точки -> **"Открыть проводник"**. В боковой панели должен появиться Shelter.

Три сценария:

* Скриншот, сделанный **внутри** профиля, вытащить в личный.
* Файл из личного закинуть в профиль.
* Открыть системный файловый менеджер ColorOS ("Файлы") -> увидит ли он Shelter как источник. На Samsung именно тут отвал (#2135, "запрещено политикой безопасности"). Что делает ColorOS -- данных нет ни одного поста.

**Прислать:** что из трех работает, и если системный менеджер отваливается -- дословный текст ошибки.

## T4. Автозаморозка против энергосбережения ColorOS

BBK агрессивно душит фон. Shelter держит процесс в профиле уведомлением -- первый кандидат на отстрел.

Настройка: Настройки Shelter -> **"Служба автозаморозки"** + **"Задержка автозаморозки"**. Автозаморозка работает только для приложений, запущенных через **"Ярлык разморозки и запуска"** -- это прямо написано в описании настройки, не для всех подряд.

Перед тестом занеси Shelter в белые списки ColorOS в обоих профилях: автозапуск, отключение оптимизации батареи.

Тест: создать ярлык разморозки для приложения, запустить через него, заблокировать экран, подождать 15 минут.

```bash
adb shell pm list packages --user <N> | grep <пакет>
```

Замороженное приложение скрыто через `setApplicationHidden` и в списке **не появится**. Появилось -- заморозка не сработала.

**Прислать:** сработала или нет, и сработала ли она же без блокировки экрана (через "Групповая заморозка" в меню).

## T6. adb в рабочий профиль

На HyperOS 3 / A16 падает с `SecurityException: Shell does not have permission to access user 11` (#2072). На ColorOS данных нет.

Безопасная проверка, ничего не удаляет:

```bash
adb shell pm list packages --user <N>
```

Если прошло -- можно проверить и удаление, но **только на заведомо ненужном пакете**, операция необратима в пределах профиля:

```bash
adb shell pm uninstall --user <N> <пакет>
```

**Прислать:** прошло или `SecurityException`.

## T7. Что ColorOS насовала в профиль сама

На HyperOS система сама включает в профиле свои приложения, которых пользователь не клонировал (#1970 -- GetApps, Безопасность). Проверить аналог у Oppo.

Shelter -> вкладка рабочего профиля -> три точки -> **"Все приложения"**. Приложение честно предупреждает, что это может ломать поведение -- читать не обязательно, но менять там ничего пока не надо, задача просто посмотреть.

```bash
adb shell pm list packages --user <N> | wc -l
adb shell pm list packages --user <N> | grep -iE "oppo|coloros|heytap|oplus"
```

**Прислать:** список пакетов Oppo, оказавшихся в профиле.

## T9. NFC -- опционально, ROI низкий

Если платежи из профиля тебе не нужны -- пропусти. Новые API Android 16 нам недоступны (только Device Owner и корпоративные профили), а на BBK вдобавок #1647: отключение Shelter уронило модуль NFC целиком.

Если все же: Настройки Shelter в **основном** профиле -> **"Заглушка платёжных сервисов"**. Это обход одного частного бага Android, а не решение NFC.

## Что дальше зависит от результатов

* **T2 дал стектрейс** -> чиню ярлык, это конкретный баг с конкретной строкой.
* **T2 не воспроизвелся** -> баг #1706 не универсален для A16, приоритет падает, из плана уходит.
* **T3 отвалился на системном менеджере ColorOS** -> тот же класс, что Samsung. Появляется вторая платформа с той же проблемой, значит чинить надо не точечно.
* **T4 не пережила энергосбережение** -> нужен свой механизм удержания, `AlarmManager` на A16 еще и урезан пересчитанными квотами standby bucket.
* **T6 упал** -> путь через adb закрыт, любые сценарии удаления системного софта в профиле отпадают.
