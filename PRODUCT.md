# Gatekeeper: продуктовая концепция

## Коротко

Gatekeeper изолирует нежелательные приложения в Android Work Profile так, чтобы для
пользователя они оставались обычными приложениями телефона. Пользователь выбирает, что
изолировать, а Gatekeeper берет на себя установку, запуск, заморозку, передачу файлов и
диагностику проблем прошивки.

Цель не в том, чтобы показать пользователю второй Android. Цель в том, чтобы вредное,
навязчивое или обязательное ПО имело минимум доступа к личной среде, а цена этого
разделения была близка к нулю.

## Проблема

На телефоне часто нужны приложения, которым пользователь не хочет давать место в личной
среде: государственные сервисы, магазины приложений, банки, корпоративные клиенты,
мессенджеры, рекламные SDK и приложения с сомнительной моделью сбора данных.

Удалить их нельзя или неудобно. Обычная установка дает им доступ к тому же пользователю,
уведомлениям, файлам, аккаунтам и набору приложений, с которыми живет пользователь.

Work Profile дает отдельного Android-пользователя с отдельными данными, аккаунтами,
разрешениями и жизненным циклом. Gatekeeper делает этот механизм пригодным для
повседневного использования.

## Почему Work Profile

Android предлагает несколько механизмов разделения, но для личного телефона они дают
разный баланс изоляции и удобства:

| Механизм | Изоляция | Повседневное удобство | Решение Gatekeeper |
| --- | --- | --- | --- |
| Work Profile | Отдельный user, данные и разрешения | Общий launcher, уведомления и кросс-профильные действия | Основной механизм |
| Private Space | Сильная скрытая зона | Требует отдельного входа, плохо подходит для постоянных приложений | Не заменяет Work Profile |
| Secondary user | Отдельная пользовательская сессия | Нужно переключать пользователя целиком | Слишком высокая ежедневная цена |
| Device Owner | Самый широкий контроль политик | Требует полного управления устройством и разрушительной настройки | Не нужен на личном телефоне |

Work Profile выбран не потому, что он идеален, а потому, что это лучший штатный компромисс:
приложение изолировано, но пользователь не должен переключать телефон в другую личность.

## Продуктовое обещание

Пользователь должен иметь возможность сказать:

> "Это приложение мне нужно, но я не хочу, чтобы оно жило в моем личном телефоне".

После выбора "Изолировать" приложение:

1. устанавливается как чистая отдельная копия в рабочий профиль;
2. не получает private data, аккаунты и разрешения личной копии;
3. может быть мгновенно остановлено и скрыто вместе с другими нежелательными приложениями;
4. остается доступным через привычный launcher, уведомления и явные действия пользователя;
5. передает файлы наружу только через понятное контролируемое действие.

Пользователь не обязан понимать, что такое user ID, DPM, intent forwarder, Binder или
фоновый процесс. Эти детали должны оставаться внутри Gatekeeper.

## Граница безопасности

### Что изоляция реально дает

- отдельные sandbox и private data приложения;
- отдельные разрешения, аккаунты, cookie, storage и media database;
- возможность разом остановить, скрыть и заморозить набор приложений;
- отсутствие прямого доступа приложения рабочего профиля к файлам личного профиля;
- контроль явных кросс-профильных действий Gatekeeper.

### Чего Gatekeeper не обещает

- не скрывает от Android и OEM сам факт существования рабочего профиля;
- не превращает телефон в полностью управляемое корпоративное устройство;
- не может штатным публичным API запретить всем приложениям `QUERY_ALL_PACKAGES`;
- не может надежно перенести private data или логин приложения между профилями;
- не может штатно передать владельца профиля между версиями, подписями или форками
  Gatekeeper: Android передает владение только другому уже активному DPC из другого package,
  после чего Gatekeeper больше не управляет профилем;
- не может гарантировать поведение проприетарных фризеров ColorOS, MIUI и других OEM;
- не делает личный VPN автоматически VPN рабочего профиля;
- не защищает от компрометации самой прошивки, root или физического захвата разблокированного
  телефона.

Если платформа не дает реальной защиты, Gatekeeper должен сказать это прямо, а не
показывать фиктивный переключатель.

## Для кого

Основной пользователь - человек, которому нужен собственный телефон, но приходится
использовать нежелательные приложения. Он хочет:

- пользоваться ими без второго телефона;
- держать личные данные отдельно;
- не разбираться в Android enterprise-интерфейсе;
- не терять фото, файлы, уведомления и быстрый доступ;
- в один жест отключать весь нежелательный набор.

Первый целевой сценарий: ColorOS 16 на Oppo Find X9 Pro Global. Поддержка других прошивок
строится через измерения и capability checks, а не предположения.

## Принципы UX

### 1. Изоляция по умолчанию, сложность по запросу

В главном экране пользователь видит приложения и действие "Изолировать", а не настройки
профиля. Технические настройки находятся отдельно и не мешают обычному сценарию.

### 2. Один телефон, а не два телефона

Личное и рабочее приложения могут быть показаны рядом, но операция должна быть цельной:

- "Установить в изоляцию";
- "Открыть";
- "Остановить все изолированные";
- "Передать файл";
- "Проверить, почему профиль не отвечает".

Слова "личный" и "рабочий" используются только там, где выбор действительно важен.

### 3. Явное направление данных

Передача файлов между профилями всегда показывает источник и получателя. Автоматические
переносы медиа возможны только как отдельная opt-in функция с точным списком директорий.
Никаких скрытых копий private data.

### 4. Никаких ложных гарантий

Переключатель существует только если Gatekeeper реально может применить и проверить
политику. Ограничения OEM, VPN и Android показываются понятным текстом с действием:
"Открой настройки батареи", "Включи Work Mode", "Это приложение нельзя клонировать".

### 5. Безопасность не должна мешать обычной жизни

Безопасные механизмы не должны вызывать белый экран, бесконечную загрузку, лишний chooser,
звуковые VPN-уведомления или необходимость вручную искать файл во втором профиле.
Если система требует явного подтверждения, Gatekeeper объясняет причину один раз.

## Основные пользовательские сценарии

| Сценарий | Результат для пользователя | Граница |
| --- | --- | --- |
| Изолировать приложение | Чистая копия ставится в Work Profile | Данные и логин не переносятся |
| Установить APK в изоляцию | APK выбирается в личном профиле и ставится в рабочий | Пользователь подтверждает установку, если потребует Android |
| Открыть изолированное приложение | Приложение открывается как обычное | Work Mode должен быть включен |
| Остановить все | Нежелательные приложения скрыты и процессы остановлены | Системные приложения могут иметь OEM-ограничения |
| Передать файл | Пользователь выбирает направление и приложение-получатель | Только явные общедоступные файлы, не private app data |
| Автоперенос скриншотов | При opt-in фото попадают в личную галерею | Только выбранные media-директории и MIME |
| Проверить надежность | Gatekeeper показывает батарею, фоновое ограничение и Work Mode | HANS и другие OEM-фризеры не всегда видны API |

## Решения в продукте

### Бесшовное клонирование

Клонирование - это установка base APK и его split APK в рабочий профиль, а не копирование
всего приложения. Gatekeeper обязан показывать результат установки, обновить список и
объяснить отказ. Фаза 19 закрепляет этот путь тестами на эмуляторе и ColorOS 16.

### Файлы без пробоев изоляции

File Shuttle дает доступ к разрешенным файлам другого профиля через SAF, а не открывает
все storage напрямую. Соединение поднимается только из видимого системного экрана, чтобы
не нарушать Android background activity launch policy. Если профиль заморожен, пользователь
видит "Подключить", а не вечный spinner.

### Мягкая остановка профиля

Auto Freeze и Batch Freeze выключают нежелательный набор по явному действию, блокировке
экрана или настройке VPN. VPN-сторож выключен по умолчанию, на тихом канале и полностью
управляется в настройках. Он не должен вмешиваться в раздельное туннелирование без
сигнала от пользователя.

### Диагностика вместо догадок

Gatekeeper проверяет доступность Work Profile, сервисов и стандартных battery policies.
Для ColorOS отдельная инструкция и измерение важнее обещания "мы все починили":
прошивка может заморозить процесс даже при корректном Android-коде.

## Приоритеты

1. Надежность основы: provisioning, запуск, кросс-профильная связь, File Shuttle.
2. Бесшовные повседневные действия: clone, APK install, open, freeze, file share.
3. Объяснимые ошибки и диагностика батареи, Work Mode и OEM-ограничений.
4. Опциональные удобства: media mirror и правила автоматизации.
5. Измерение остаточных рисков сторонними детекторами только на эмуляторе.

Полное ревью и финальныи регресс обязательны, но не должны вытеснять пользовательские
поломки в первых трех пунктах. Без отдельного совместимого Owner Companion перенос владения
намеренно не предлагается: необратимая кнопка не является удобством.

## Критерий успеха

Gatekeeper успешен, если пользователь может установить нужное, но нежелательное приложение
в изоляцию, пользоваться им, при необходимости передать один файл и одной кнопкой остановить
весь набор - не сталкиваясь с техническими деталями и не теряя контроль над личной средой.

## Необходимые проверки перед заявлением поддержки устройства

Для каждой целевой прошивки фиксируются:

1. создание и включение Work Profile;
2. clone обычного приложения и split APK;
3. запуск после 1, 10 и 60 минут простоя;
4. File Shuttle и обмен файлами в обе стороны;
5. Auto Freeze, Work Mode и уведомления;
6. работа с личным VPN и отдельным VPN рабочего профиля;
7. поведение после обновления Gatekeeper поверх существующей установки.

Без такого протокола фраза "поддерживается" не используется.
