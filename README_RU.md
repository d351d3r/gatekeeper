# Gatekeeper

Gatekeeper изолирует нежелательные приложения в Android Work Profile: отдельном
пользователе системы со своими данными, аккаунтами, разрешениями и жизненным циклом.
Клонированные приложения выглядят и работают как обычные, но не видят личную среду
владельца телефона.

**Репозиторий:** [d351d3r/gatekeeper](https://github.com/d351d3r/gatekeeper)

Продуктовая концепция и границы платформы: [PRODUCT.md](PRODUCT.md).
English version: [README.md](README.md).

## Что нового в 1.5.3

- **Автокопирование медиа из рабочего профиля** — новые скриншоты и фото/видео
  камеры из рабочего профиля появляются в личной галерее при подключении File
  Shuttle (выключено по умолчанию). Модель «догоняющего водяного знака»: без
  постоянного сервиса, файлы, появившиеся пока связь была мёртва, догоняются при
  следующем подключении, дубликаты пропускаются. Только направление
  work → personal. Подробности: [docs/feature_media_mirror.md](docs/feature_media_mirror.md).
- **Корневые сертификаты для рабочего профиля** — установка root CA только в
  рабочий профиль: SHA-256-отпечаток показывается перед установкой, установленные
  сертификаты перечисляются и удаляются в один тап. Браузеры честят пользовательское
  хранилище CA, большинство приложений (targetSdk 24+) — нет. Подробности:
  [docs/feature_ca_certs.md](docs/feature_ca_certs.md).
- **Список автозаморозки стал полностью ручным** — приложения, установленные
  магазинами внутри рабочего профиля, больше не добавляются в список автоматически;
  включайте метельник на нужном приложении. Фоновый механизм авто-добавления откачен:
  на стоковом Android 16 `PACKAGE_ADDED`-receiver'ы не доставляются, а кросс-профильная
  отправка из рабочего профиля не находит получателей — механизм всё равно срабатывал
  только при открытии списка приложений.
- **Обновление с более ранних сборок требует пересоздания рабочего профиля**
  (сменился компонент device admin) и повторного закрепления ярлыков / выдачи
  папок SAF.

## Возможности

- **Клонирование приложений** в изолированный рабочий профиль (установка из личного
  профиля или APK на устройстве).
- **Заморозка и разморозка** отдельных приложений: ярлык исчезает, процессы убиваются,
  приложение не может запуститься в фоне.
- **Автозаморозка** — список приложений, которые замораживаются вместе по блокировке
  экрана, из панели инструментов, по событию Anti Spy или ярлыком на рабочем столе.
- **Групповая заморозка/разморозка** одним действием из панели, настроек или ярлыков.
- Замороженные приложения поднимаются в начало списка рабочего профиля.
- **Anti Spy** — обнаружение стороннего VPN, диалог принудительной заморозки списка
  и «заглушка» VPN при запуске защищаемого приложения.
- **File Shuttle** — передача файлов между личным и рабочим профилем через Storage
  Access Framework: документы открываются в нужном профиле без копирования данных.
- **Автокопирование медиа** — новые скриншоты и фото/видео камеры из рабочего профиля
  появляются в личной галерее при подключении File Shuttle (выключено по умолчанию).
- **Корневые сертификаты для рабочего профиля** — установка корневого CA только в
  рабочий профиль: с отпечатком SHA-256 перед установкой, списком и удалением в один тап.
- Мастер первоначальной настройки и диагностика проблем прошивок.

Инструкция для пользователя (русский): [USER_GUIDE.md](USER_GUIDE.md).
Известные проблемы и тестовые заметки: [PROBLEMS.md](PROBLEMS.md).

## Ограничения (стены платформы)

Это границы Android и прошивок, а не баги Gatekeeper — ни одно приложение
этого класса их не обходит:

- **Видимость VPN.** Приложения внутри рабочего профиля видят, что VPN
  включён (интерфейс tun0), даже когда VPN работает только в личном профиле.
  Практические обходы: поднимать VPN *внутри* рабочего профиля либо полагаться
  на автозаморозку Anti Spy при включении VPN.
- **NFC-оплата.** Платёжные приложения, установленные только в рабочем
  профиле, на большинстве прошивок не попадают в выбор «оплата по умолчанию»
  (на части устройств работает, напр. свежие Honor). Встроенная «заглушка
  платёжного сервиса» обходит лишь один конкретный баг Android.
- **Заморозка и работающие процессы.** Скрытие приложения не убивает уже
  запущенный foreground-процесс (музыка играет дальше); Gatekeeper лишь
  best-effort останавливает фоновые процессы.
- **Скриншоты остаются в профиле.** Скриншот внутри рабочего профиля падает
  в хранилище профиля; Media Mirror автоматически копирует скриншоты и фото
  камеры в личный профиль.
- **Фейковую геолокацию нельзя применить только к профилю** — подмена
  геолокации общесистемная.
- **Вендорские ограничения ADB.** Часть прошивок (HyperOS, ColorOS) блокирует
  `pm ... --user <профиль>` для shell — зачистка профиля через ADB непереносима.
- **Частное пространство** (Private Space, Android 15+) решает другую задачу,
  чем рабочий профиль: прячет приложения за отдельной блокировкой, а не
  изолирует недоверенные приложения. Подробности — в USER_GUIDE.

## Требования

- Android 7.0+ (API 24+).
- Устройство с корректной реализацией Work Profile (AOSP-подобные прошивки;
  сильно переработанные оболочки вендоров могут ломать функции профиля).

Проверено на Samsung Galaxy S24 Ultra (SM-S928B/DS) и Galaxy Tab S9 FE+ (SM-X616B),
на стенде AOSP 16 (эмулятор) в ходе разработки.

## Сборка

Нужен JDK 17 и Android SDK (compileSdk 36, build-tools 36.0.0).

```sh
git clone https://github.com/d351d3r/gatekeeper.git
cd gatekeeper
./gradlew :app:assembleDebug      # debug APK
./gradlew :app:assembleRelease    # release APK (minify)
```

Готовый APK копируется в корень репозитория как
`Gatekeeper-{version}-({versionCode})-{debug|release}.apk`. Номер версии берётся из
[version.properties](version.properties) и может быть переопределён:
`./gradlew :app:assembleDebug -PversionCode=400`.

Проверки перед сборкой (те же, что в CI):

```sh
./gradlew :app:lintDebug :app:detekt :app:testDebugUnitTest
```

## CI

Каждый пуш в `main` проходит пайплайн [.github/workflows/android.yml](.github/workflows/android.yml):

1. **Gate** — Android lint → статический анализ detekt (с baseline) → юнит-тесты.
2. **Build** — только после зелёного gate: бот коммитит бамп `VERSION_CODE` и собирает
   **arm64-v8a debug и release APK** с новым номером версии. Артефакты и SHA-256
   прикрепляются к прогону.

## Подпись

APK, собранные CI из `main`, подписываются одним **приватным project-keystore**:
ключ лежит в GitHub Secrets (`CI_RELEASE_KEYSTORE*`), CI подписывает им и debug,
и release, поэтому оба артефакта взаимозаменяемы и всегда ставятся поверх
старого APK. Посторонний этим ключом подписать ничего не может; сборки форков и
чужих PR падают на публичный fallback-ключ `app/gatekeeper.keystore` — у них
другая подпись, поверх CI-сборок они **не** установятся.

Храни свою приватную копию keystore: если потеряешь и её, и секрет GitHub,
подпись невосстановима — на каждом устройстве приложение придётся удалить и
поставить заново (сначала экспортируй настройки: удаление приложения сносит
рабочий профиль).

Релизы публикуются тегами `v*` — см. [.github/workflows/release.yml](.github/workflows/release.yml).

## Структура репозитория

- `app/` — приложение (Kotlin, AIDL).
- `tools/` — служебные скрипты: `testbench.sh` (стенд проверки на эмуляторе через
  ADB), `repackage-google-play.sh` (сборка варианта для Google Play без
  MANAGE_EXTERNAL_STORAGE).
- `docs/` — модель угроз, спецификации фич.
- `assets/` — исходники иконок тулбара/ярлыков.

## Удаление приложения

Сначала удалите рабочий профиль в настройках системы, затем удалите Gatekeeper
обычным способом. Удаление только значка не удаляет профиль и клонированные
приложения.
