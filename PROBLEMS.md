# Известные проблемы

Тестовые устройства: Samsung Galaxy S24 Ultra (SM-S928B/DS), Tab S9 FE+ (SM-X616B),
AVD `gatekeeper_a16` (AOSP 16, google_apis).

Дорожная карта по всем багам (включая аудит 4PDA) — в [plan.md](plan.md).
История тестов и исправлений — в git; этот файл держим коротким: только то,
что открыто прямо сейчас.

## Открытые

### Galaxy Store не клонируется в рабочий профиль

**Статус:** отложено, план E-1. **Пакет:** `com.sec.android.app.samsungapps`.
System-пакет, в профиле не установлен: `enableSystemApp()` тихо не отдаёт его;
экспериментальный `needsPackageInstallerClone` откатан (краш). Play Store и
прочие клонируются нормально. Последнее подтверждение: build 191 (сценарий G3).

### Первое включение VPN блокируется

**Статус:** план E-2, нужна перепроверка на текущем билде.
Симптом (build 191): первый тап «подключить VPN» не подключает, второй —
подключает. Пересечение `AntiSpyVpnWatchService`/`AntiSpyDummyVpnDisconnector`
с пользовательской попыткой поднять туннель.

### Toast «Все приложения заморожены» в шторке рабочего профиля

**Статус:** план E-3, нужна перепроверка на текущем билде.
Сообщение групповой заморозки уходит вниз, среди уведомлений рабочего профиля,
а не toast сверху. Направление: убрать `postVpnAutoFreezeSuccessAlert` при
ручной/ярлыковой заморозке, оставить `showToastOnMainProfile`.

### Двойной диалог «Установить приложение?» при клонировании

**Статус:** план E-4, нужна перепроверка на текущем билде.
Симптом (185–191): диалог дважды, иногда первый тап мимо. Направление:
`installExistingPackage` (API 28+) + guard `PENDING_USER_ACTION`.

### Стартовая групповая заморозка при загрузке

**Статус:** наблюдение, план E-5. После 185 сообщалось о лишнем «Заморозить всё»
при reboot; на Tab S9 FE+ (build 191, F3) не воспроизведено. При воспроизведении:
морозить только не скрытые, стартовать из фона.

### Фоновая автозаморозка сторовых установок — осознанно откачена

**Статус:** решение зафиксировано (сентябрь 2026), план E-6.
`PACKAGE_ADDED` манифест-ресивер мёртв на targetSdk 35; доставка work→parent
через CPIF не резолвится на AOSP 16 (на Samsung builds 231/235 работала).
Механизм (`WorkPackageScanJobService` + `WorkPackageReportReceiver`) вырезан.
Список автозаморозки полностью ручной (opt-in снежинкой).

**Остаток-ограничение:** пакеты, установленные в профиль ДО первого открытия
списка приложений, становятся базлайном и никогда не автозаморозятся.

### MediaMirror: относительный путь молча клампится в корень

**Статус:** план E-7. `FileShuttleService.resolvePath` понимает только
абсолютные пути чужого профиля или `DUMMY_ROOT + dir`; относительный путь
превращается в корень. Контракт для клиентов: ходить только через
`DUMMY_ROOT + dir`.

### Флака теста `foregroundNotificationIsSilent`

**Статус:** план E-3 флаки-эпизод Фазы 16; при повторяемости изолировать.

## Границы платформы (не баги Gatekeeper)

- VPN-детект из профиля (tun0 виден приложениям) — не лечится, см. README.
- NFC-платежи из рабочего профиля — зависит от прошивки; `PaymentStubService`
  обходит только один частный баг Android.
- Заморозка (`setApplicationHidden`) не гарантирует остановку уже запущенного
  процесса — поведение платформы.
- adb `pm --user N` закрыт на ряде прошивок (HyperOS, ColorOS).
- work→parent CPIF может не резолвиться на AOSP 16 (стенд), на Samsung
  работает.
