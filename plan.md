# План: аудит и починка болей из темы 4PDA (Shelter, topic 917380)

Статус: черновик плана. Источники: `docs/4pda_*.md`, `docs/shelter_4pda_posts.json`
(2142 поста, дамп 10.08.2026). Номера `#NNNN` — посты темы.

## Правила работы по каждому пункту

1. **Аудит** — сначала проверить фактическое поведение в коде Gatekeeper
   (не полагаться на то, что «должно работать»). Результат фиксируется
   одним из статусов: `OK` (работает, есть покрытие), `GAP` (работает,
   покрытия нет / покрытие слабое), `BUG` (воспроизводится или кодом
   подтверждено), `N/A` (платформенное ограничение — только документация).
2. Если `BUG` — чинить в отдельной ветке от `main`, минимальный дифф.
3. Каждый фикс — с тестами. Тип теста выбирается по слою:
   - чистая логика → JVM unit test (`app/src/test`, паттерн: `MiuiDetectorTest`,
     `AntiSpyWatchPolicyTest`, `VpnRoutingAdviceTest`);
   - работа с системой/profile APIs → инструментальный тест
     (`app/src/androidTest`, паттерн: `DocumentsProviderTest`,
     `AntiSpyVpnWatchTest`, AVD `gatekeeper_a16`);
   - то, что воспроизводится только на вендорских прошивках (MIUI/HyperOS,
     OneUI/Knox, ColorOS) → автоматизировать нельзя, оформляется как
     ручной сценарий в PROBLEMS.md + защитный код + unit-тест политики.
4. Зелёный CI (`lint → test → connectedCheck на AVD` если применимо → build)
   обязателен до мержа. Ничего не помечать «исправлено» без прогона.

## Блок A. Баги, унаследованные от апстрима (Shelter)

### A1. Установка APK внутри профиля на MIUI/HyperOS — «висяк» — P0

Симптомы: установка APK из профиля висит/«установщик не отвечает»,
кнопка «всё равно продолжить» ведёт в тупик (#2105, #2113, #867, #1046).
В апстриме дыра: гард `isMIUI()` есть только на одном пути, путь
`installApk` (через системный установщик) гарда не проходит; `isMIUI()`
читает `ro.miui.ui.version.name` через getprop и на HyperOS может
молча отвалиться (docs/4pda_code_verification.md).

- [x] Аудит (12.09.2026): **BUG подтверждён в Gatekeeper**. Гард MIUI есть
      только на пути клонирования (`AppListFragment:288`). Путь установки APK
      (`GatekeeperService.installApk` → `DummyActivity.actionInstallPackage`,
      строки ~266–324) гарда не проходил — ровно дыра апстрима. `MiuiDetector`
      читает `Build.MANUFACTURER/BRAND/DISPLAY` (надёжнее getprop-варианта
      апстрима, ловит xiaomi/redmi/poco и HyperOS по display).
- [x] Фикс: новый `InstallWarnPolicy` (предупреждать на MIUI только в
      рабочем профиле) + диалог в `DummyActivity` до запуска сессии установки;
      отмена отвечает вызывающему `RESULT_CANCELED` и чистит forward-proxy,
      вместо молчаливого висяка. Строки `miui_install_apk_warning` (en/ru).
- [x] Тесты: `InstallWarnPolicyTest` (JVM, 3 кейса: MIUI+work / MIUI+main /
      non-MIUI) — зелёные; `MiuiDetectorTest` — зелёный; `lintDebug` +
      полный `testDebugUnitTest` — зелёные.
- [ ] Ручной сценарий на реальном Xiaomi для PROBLEMS.md (нужен стенд).

### A2. Ярлык общей заморозки крашится на Android 16 — P0

(#1706; [С] в матрице, гипотеза — adaptive-icon через
`Icon.createWithResource` vs растр).

- [x] Аудит (12.09.2026): гипотеза апстрима в Gatekeeper **не воспроизводится в
      части иконки**: ярлык общей заморозки собирается через
      `createBatchShortcutIcon` — декодированный PNG, сплющенный до непрозрачного
      растра ≤512px, `Icon.createWithResource` на пути нет (только недостижимый
      fallback). Найден соседний дефект: `Utility.createLauncherShortcut` звал
      `requestPinShortcut`/`createShortcutResultIntent` без try/catch — исключение
      системы/лаунчера уходило бы в краш вызывающего (ровно симптом #1706).
- [x] Фикс: try/catch вокруг пина ярлыка → отказ превращается в тост
      `unsupported_launcher`, приложение не падает.
- [x] Тесты: `BatchShortcutIconTest` (androidTest) — контракт иконки
      (bitmap-backed, ≤512px) и приёмка `ShortcutInfo.Builder`; компиляция
      зелёная, прогон на AVD `gatekeeper_a16` — в ручной сессии (образов
      эмулятора на машине нет).
- [ ] Ручной сценарий: создать ярлык общей заморозки на AVD AOSP 16 /
      PROBLEMS.md-запись.

      10 с+» в `DocumentsProviderTest` — на прогоне AVD `gatekeeper_a16`

- [ ] Тесты: `DocumentsProviderTest` дополнить — (а) вызов методов при
